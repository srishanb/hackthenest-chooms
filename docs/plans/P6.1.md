## Goal

A first-time player lights the lantern in under a minute: a short intro, an active-play step and a resting step,
each with a plain pass or fail message, retry, and a clear fallback. The same screens reopen from the pause menu,
the HUD's signal warning and the ember prompt. All wording follows the framing rule.

## What exists already (pre-code check)

- `src/ui/components/calibration/calibration.ts`: a **stub** (`visibleIn: ['calibrating']`, renders nothing).
- `SignalHandle.control.calibrate(step)` (`src/signal/index.ts`): runs one step for `SIGNAL_CONFIG.calibration
  .activeMs` or `.restingMs` (12 s each today), then resolves `{ step, ok, reasonKey? }` and emits
  `calibration_result`. It **throws** if a step is already running.
- `src/signal/pipeline.ts`: each step is **two equal halves**. First half = LOW window (relaxed / eyes open),
  second half = HIGH window (jaw clench / eyes closed). The split is at exactly half the configured duration.
- Reason keys from `src/signal/stages/calibration.ts`: `calibration.tooFewSamples`, `calibration.unstable`,
  `calibration.noSeparation`. They name no step, so the screen picks a per-step wording.
- `isCalibrated()` needs the **resting** baseline always, plus the active baseline unless `mode === 'fixed'`.
  So `setMode('fixed')` rescues only a failed active step. If resting fails, `valid` stays false, every effect stays
  at neutral, and the ember can only use the labelled ordinary-input rescue (EMB-9).
- The debug overlay (Srishan's) already has **Calibrate active / resting** buttons; reuse its call pattern, not its
  code. PR 17 adds `connect('LIVE_EEG')` (the Bluetooth picker opens only if nothing is awaited before it).
- **Nothing ever sets `phase: 'calibrating'`**: the game owns the snapshot and starts in `'playing'`.
- Amrit's P2 notes the main-menu start route is still undefined; this plan does not decide it.

## Tasks and acceptance tests

### P6.1.1 Flow logic (pure) and wording

1. `calibration-flow.ts`: a reducer `stepFlow(state, input) → state` with screens `intro → source → activeLow →
   activeHigh → activeResult → restingLow → restingHigh → restingResult → done`. Inputs: `start`, `tick(nowMs)`,
   `result(CalibrationResult)`, `retry`, `useSteadyLight`, `continueWithout`, `close`. It returns the next state
   plus an optional command (`calibrate(step)` or `setMode('fixed')`) that the screen runs. The halfway cue is
   `startMs + durationMs / 2`; `durationMs` comes from config, so tests use a fake clock.
2. Fail rules: active fail offers **Retry** and **Use steady light** (`setMode('fixed')`, then on to resting).
   Resting fail offers **Retry** and **Continue without it** (honest copy: lighting stays steady and the ember uses
   the labelled rescue). After two fails of one step, the fallback button is shown first.
3. `messageKey(step, reasonKey)` → a string key such as `calib.fail.noSeparation.resting`; an unknown or missing
   key gives `calib.fail.unknown`. Never show a raw key.
4. Add the `calib.*` strings to `strings.ts`. Framing: name the signal composure; say muscle activity (the jaw) is
   part of it; say **eye closure is not proof of calmness**; no medical or therapy claims; a failed step "says
   nothing about you". Never use "emotion" or "stress".

| Acceptance test | How |
|---|---|
| Happy path | Unit test: start, ticks to half (screen turns `activeHigh`), ok result, same for resting → `done`. |
| Cue at exactly half | With `activeMs = 12000`, the screen is `activeLow` at 5999 ms and `activeHigh` at 6000 ms. |
| Active fail → steady light | `ok: false`, then `useSteadyLight`: command `setMode('fixed')`, screen `restingLow`. |
| Resting fail is honest | `ok: false`, then `continueWithout`: `done` with `restingCalibrated: false`. |
| Unknown reason | `reasonKey: 'x.y'` and `undefined` both give `calib.fail.unknown`. |
| Wording rule | Unit test: no `calib.*` string contains "emotion", "stress", "diagnos", "therap" or "medical". |

### P6.1.2 Screens

1. Render each screen in the `full` slot: a lantern that brightens as each half completes, one instruction line, a
   countdown bar, and at most two buttons. Styles use only `var(--…)` from `tokens.css`.
2. **Source screen.** Show the badge text. Wait until `reader.getState()` has `sampleAgeMs < staleAfterMs`, then
   enable Start. If the URL is `?source=live` and no data arrives, show **Connect Octopus 16**: its click handler
   calls `control.connect('LIVE_EEG')` as its **first statement, with no `await` before it**. A rejected promise
   shows `calib.connectFailed` (Chrome or Edge, close the cloud.pieeg.com tab, check power). On the simulator,
   show the key hint (`Digit2` clench, `Digit1` alpha toggle) from `SIGNAL_CONFIG.simKeys`.
3. While a step runs, disable every button (a second `calibrate` call throws) and catch a thrown call as a failure.
4. **Sound cues for eyes closed.** `cue-tone.ts` plays a short tone at the resting halfway ("close your eyes") and at
   the end ("open your eyes"), at `master × sfx` volume. It is UI-local because the UI may not import the audio lane
   and no cue event exists. The Start click unlocks audio. Web Audio names are unverified: check MDN.
5. Keyboard: Enter starts or retries, Escape closes (only between steps). Focus moves to the main button.
