## Goal

Four new platform behaviours, each one file plus one registry line, each on a fixed, visible cycle that runs on game
time and never reads the signal. None makes the climb harder to finish than Core: moving and disappearing platforms
are never ember anchors, and the climb stays completable with every disappearing platform treated as gone.

## Tasks and acceptance tests

### P11.0 Shared groundwork (first, about 45 min)

1. `game-clock.ts`: game time in ms that advances only while `phase` is `'playing'`: it stops on `pause` and during
   ember activation (EMB-4 freezes hazards). Every cycle reads this clock, never `performance.now()`.
2. Registry entry gains `hazard: boolean` (drawn by the protected layer) beside P4's `stationary` and `anchorSafe`.
3. `environment.ts`: `PlayerEnvironment { grip01: number; windAccelX: number; carryDx: number; carryDy: number }`,
   passed into `stepPlayer`; the default (`1, 0, 0, 0`) leaves Core movement unchanged. Plain numbers only: the
   player folder still never imports the composure contract.

| Acceptance test | How |
|---|---|
| Core movement unchanged | Unit: P4.1's existing tests pass with the default environment. |
| Clock stops | Unit, fake bus: after `pause` or ember activation the clock does not advance; after `resume` it does. |
| No signal anywhere | `rg -n "composure" src/game/world/platform-types src/game/player` prints nothing. |

### P11.1 Slippery surfaces (PLT-6, about 45 min)

1. `ice.ts`: `{ stationary: true, anchorSafe: true, hazard: false }`; standing on it sets `grip01 = iceGrip01`.
2. Movement: on ground, horizontal speed moves toward the walk target at a rate scaled by `grip01`, so you slide but
   steer the same way every time. Launch speed and angle are unchanged (MOV-4).
   Drawn in a distinct colour with a pale top edge (Neil's art later).

| Acceptance test | How |
|---|---|
| Consistent | Unit: same input on ice twice gives identical positions; stopping distance is longer than on static. |
| Jump unchanged | Unit: a launch from ice equals a launch from static with the same charge. |
| Looks different | Browser: ice is told apart from static at a glance, also at intensity 1. |

### P11.2 Moving platforms (PLT-3, about 1.5 h)

1. `moving.ts`: position is a pure function `platformPosition(p: PlatformData, tMs: number): { x: number; y: number }`
   (back and forth along `motion`). `{ stationary: false, anchorSafe: false, hazard: false }`. A thin track line
   shows the whole path, so the cycle is visible before you jump.
2. Collide: standing on one adds its per-step displacement (`carryDx`, `carryDy`), so the rider moves with it.
3. `check-levels`: try launches at eight evenly spaced cycle phases; a moving platform counts as reachable only if it
   is reached in at least two neighbouring phases (there is a real timing window).

| Acceptance test | How |
|---|---|
| Predictable | Unit: `platformPosition` at `t` and `t + periodMs` are equal; it never leaves its track. |
| Carries the rider | Unit: standing still on it for one period returns you to the start position. |
| Never an anchor (EMB-3) | Unit: P6.2's anchor choice skips a moving platform and picks the static ledge before it. |
| Level check | `npm run check:levels` passes with one moving platform; fails on a fixture with a too-short window. |

### P11.3 Disappearing platforms above catch platforms (PLT-4, about 1 h)

1. `disappearing.ts`: `vanishState(p, tMs): 'solid' | 'warn' | 'gone'` from `vanish`; `gone` is not solid.
   `{ stationary: true, anchorSafe: false, hazard: true }`.
2. Warning: during `warn` the protected layer draws its outline in a warning colour that pulses; under reduced
   motion it changes colour without pulsing. The warning shows through any darkness (LAN-3).
3. `check-levels`: every disappearing platform has a static catch platform below it within one jump of where it
   was; and the whole climb stays reachable with every disappearing platform treated as gone, so they are
   shortcuts, never the only route (the "core climb" deferral in PLAN.md stays respected).

| Acceptance test | How |
|---|---|
| Fixed cycle | Unit: states repeat every `solidMs + warnMs + goneMs`; `warn` always comes before `gone`. |
| Never an anchor | Unit: anchor choice never returns a disappearing platform. |
| Catch rule | `check:levels` fails on a fixture with no catch platform below a disappearing one. |
| Warning readable | Browser, intensity 1: the warning is visible before the platform goes. |

### P11.4 Wind section (PLT-5, about 1.5 h)

1. `wind.ts`: `windAt(zones, x, y, tMs): number` gives horizontal acceleration; gusts on fixed `gustMs` / `calmMs`
   cycles. Inside a zone it feeds `windAccelX`. Never stronger than authored, never from the signal.
2. `wind-cues.ts`: drawn streaks show direction; they speed up a moment before and during a gust. Under reduced
   motion: static arrows that brighten during a gust.
3. `check-levels`: platforms in a wind zone must be reachable both with the gust on and with it off.

| Acceptance test | How |
|---|---|
| Predictable gusts | Unit: `windAt` repeats every `gustMs + calmMs`; zero outside every zone. |
| Bounded | Unit: a gust shifts a landing by at most `accelPxPerS2 × airtime² / 2`; air steering still works. |
| Visible cue | Browser: a first-time player can say which way the wind blows before jumping. |
| Level check | `check:levels` fails on a fixture ledge reachable only with the gust off. |

## Risks

| Risk | Response |
|---|---|
| Moving platforms break `check-levels` | Phase sampling (P11.2 task 3) with a two-phase timing window. |
| Carry feels jittery with one-way collision | Apply carry before the collide step; test a whole period standing. |
| Wind makes the search slow | Only two wind cases per zone; zones are small. |
| Ice or windy ledges as anchors feel unfair | **Open question for Ali:** `anchorSafe` true or false for them. |

## Cut line

Drop first: wind (P11.4), then disappearing (P11.3), then moving (P11.2). Smallest useful version: P11.0 plus
slippery surfaces (P11.1). Shipping none is acceptable: all four are Expansion, and the Core climb is unchanged.

## Out of scope

Anything driven by EEG (signal-driven wind is deferred, signal-driven geometry is cut). Procedural platforms. Pulsing
platforms on the only route. Hazards that hurt. Changes to gravity, jump or steering. Narrator lines for new types.
