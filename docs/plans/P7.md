## Goal

A sarcastic narrator comments on the climb and the fall, never on the player. Lines are drafted with Gemini ahead
of time, read and edited by a human, voiced once by ElevenLabs into local files, and played by a director that
respects cooldowns, precision jumps, mute and volume. With no keys at all, captions alone carry the narrator.

### P7.1 Draft lines with Gemini (a human approves every line)

1. `draft-lines.ts`: for each trigger, ask Gemini for about eight candidates in the approved personality (H-10).
   The prompt says: comment on the climb, the fall, gravity and the rocks; never on the player's feelings, worth,
   body or health; at most 14 words; no real people. Write `tools/narrator/drafts/<stamp>.md`, never `lines.ts`.
2. `line-rules.ts`: `checkLine(text): string[]` flags words such as emotion, stress, anxious, calm down, loser,
   stupid, worthless, health, and lines over 14 words. Drafts show the flags beside each line.
3. **Neil (with Amrit) reads the drafts and hand-edits two or three lines per trigger into `lines.ts`.** If H-09 is
   late, they write them by hand from the ten H-10 samples; this task is then skipped.
4. Keys: read from `process.env`, never printed, never in a `VITE_` variable. A missing key exits with a message
   naming the variable only.

| Acceptance test | How |
|---|---|
| Rules catch bad lines | Unit test: "You seem stressed" and a 20-word line are flagged; "Gravity: undefeated." not. |
| No key, clean exit | `npm run narrator:draft` without the key exits 1 and prints only "GEMINI_API_KEY is not set". |
| Every shipped line was read | `lines.ts` header names the reviewer; `checkLine` is empty for every shipped line. |

### P7.3 Director and player (needs no keys)

1. `director.ts` (pure): `decide(state, event, tMs, lines, config, random) → { state, lineId | null }`. It maps
   events to triggers (`fall` → `bigFall` when `big`, `refuge_enter` → `refugeFirst` or `refugeAgain`, and so on),
   skips while `precision_window` is active, between `pause` and `resume` events (whether the game also writes
   `phase: 'paused'` is Ali's call), while `phase` is `'ember'`, and while a line is playing. Calibration needs no
   rule: P6.1 opens it only from the menu, pause or ember, where the narrator is already silent.
   Global gap `cooldownMs`; the same line not again within `repeatCooldownMs`; a random pick among the rest.
2. **Raise `cooldownMs` to 12000** in `audio.config.ts` (audio lane owns the value). At 8000, falls at 0 s and
   9 s would both speak, so "three falls in ten seconds, at most one line" could never pass.
3. `player.ts`: plays the clip (`line.clip`, else `assets/audio/narrator/<id>.mp3`) on P5.4.2's narrator bus at
   `master × narrator` volume. A missing clip is silent but still waits an estimated length (about 70 ms per
   character, at least 1.5 s), so captions and cooldowns behave the same. Emits `narrator_line` when a line starts.
4. Volume 0 (mute): the director still decides and emits `narrator_line`, so captions still show.

| Acceptance test | How |
|---|---|
| Three falls, one line | Unit test: `fall` at 0, 4 and 9 s → exactly one line. |
| Quiet in precision jumps | Unit test: `precision_window { active: true }`, then `fall` → no line until it ends. |
| No charging line | Browser, needs Ali's emit: hold Space and fall off an edge: no line starts while charging. |
| No repeat | Unit test: with one line per trigger, a second fall after 13 s gives no line (repeat cooldown). |
| Placeholders work | Browser with no clips: a fake `fall` event in DevTools shows a caption (P2.4) and logs no error. |

## Parallel work

P7.3 starts at once; it does not need keys, dependencies or lines (tests use fixture lines). P7.0 runs at the
same time. P7.1 waits for P7.0 and the dependency; P7.2 waits for P7.0, H-10 and approved lines. The player waits
for P5.4.2's engine; if that is late it uses one `HTMLAudioElement` per clip (unverified API, check MDN).
