## Goal

The light radius follows the composure signal smoothly and within caps, while the platform underfoot, reachable
ledges and hazards stay readable. Fog, shadows and background motion follow it too, always ease back and never
accumulate. Poor signal, fixed mode and refuges all lead to calm, full visibility. Movement and physics never change.

| Acceptance test | How (unit tests unless marked) |

### P5.2 Lantern with protected visibility (real sections need P4.2; fixtures before)

1. **Approach: depth ordering**, the P0 path. Back to front: background −10, world 0, player 10, fog 50,
   darkness 100, protected 200, in one table `effects/depths.ts` (moved out of the scene). Checked in the Phaser 4
   guides (`skills/sprites-and-images`, `skills/graphics-and-shapes`, `skills/game-object-components`) and
   `types/phaser.d.ts`: `setDepth`, `setAlpha`, `Graphics.lineStyle`, `Graphics.strokeRect`, `textures.createCanvas`.
2. **Why not masks or filters:** Phaser 4 masks are filters (`filters.internal.addMask`; `skills/v3-to-v4-migration`
   §3, `skills/filters-and-postfx`); `GeometryMask` is Canvas-only. `Phaser.AUTO` may fall back to Canvas, and
   whether filters work there is **unverified**. Depth ordering needs neither.
3. `lantern.ts`: `createLantern(scene)` and `updateLantern(lantern, x, y, frame)` wrap `darkness.ts`, read
   `frame.lanternRadius` and keep the `minCoveringRadius` guard. Higher intensity, smaller radius (LAN-2). No fuel.
4. `reach.ts` (pure): `reachablePlatforms(from: PlatformData, all: readonly PlatformData[], cfg: GameConfig):
   string[]`. First a conservative envelope from `GAME_CONFIG` (rise `(maxSpeed·sin angle)² / 2g`); once P4.1 lands,
   P4.2's search with `stepPlayer` (ask P4 to keep that search pure under `src/game/world/` so both can import it).
5. `protected-visibility.ts`: above the darkness, a thin outline of the current platform, the top edges of reachable
   platforms, and hazards if a platform type is flagged one (Core has none; P11's warnings reuse this layer).
   **Outlines and edges only**, never fills, so the darkness still matters. Colour and line width are named
   constants in the file header (see the deviation under Contract changes).

| Acceptance test | How |
|---|---|
| Reach is conservative | Unit, fixture sections: a ledge in the envelope is listed; one 50 px past it is not. |
| Current platform excluded | Unit: the platform you stand on is never in the reachable list. |
| Next ledge readable (LAN-3) | Browser, sim, clench held: from 3 non-refuge platforms per section, next ledge seen. |
| The light never goes out | Browser: intensity held at 1 for 30 s; the player and nearby ground stay lit. |
| Darkness still matters | Screenshot at intensity 1: platforms out of reach show no outline. |

### P5.3 Reversible fog, shadows and background motion (can start now, on test tables)

1. `fog.ts`: one large image at depth 50 (a soft texture drawn in code until Neil's art lands), alpha =
   `fogDensity`. It sits under the protected layer, so fog never hides the platform underfoot or the next edge.
2. `shadows.ts`: `shadowDepth` is the opacity of the darkness outside the light; it sets the darkness image's alpha.
   Neil sets that row's range as alpha (suggested 0.75–0.95), so code has no mapping constant. Today's neutral 0.4
   would be too thin, so shadows start after Neil's row change. Shadows own the sheet alpha; P8.4 flicker multiplies.
3. `background.ts`: a `TileSprite` at depth −10 with `setScrollFactor` below 1 (distant scenery only). Each frame
   `tilePositionX` advances by `backgroundMotion × MAX_DRIFT_PX_PER_S × dt` (a named header constant). The signal
   sets speed, never position, so nothing builds up. Checked in `phaser.d.ts`: `TileSprite`, `tilePositionX`.
4. **Reduced motion:** the renderer checks `settings.reducedMotion` and draws static, because the row's neutral (0.2)
   would still drift. This matches P8.4's request; P8.4 later adds sway and distortion to this same file.
5. Each renderer reads one `EffectId` from `stores.effects`. Deleting a renderer and its create call breaks nothing.

| Acceptance test | How |
|---|---|
| Nothing accumulates (ATM-2) | Unit, per row: 60 s at 1, 20 s at 0 → back within `(max−min)·e^(−20000/tau)`. |
| Recovery and reduced motion | Browser, sim: clench 20 s, relax 20 s → as at first. Reduced motion on → no drift. |
| Camera and platforms never move | `rg -n "cameras" src/game/effects` finds nothing; no renderer touches platforms. |
