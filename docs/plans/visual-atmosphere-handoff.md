## Assessment

The forest already has the right foundation: local textures loaded once in BootScene, separate presentation helpers, deterministic seeds, existing camera follow, and one bounded forestCorruption field. Preserve these. forest-world.ts currently creates viewport-sized TileSprites for forest-back/front and Dark Forest canopy/leaves, scales their tiles 2x, then scrolls tilePositionY using camera.scrollY times parallax / pixelScale. The 416x256 Ancient images therefore repeat their complete composition vertically. Dark layers have different native heights, adding competing repetition periods. This directly explains repeated arrangements; actual texture-edge continuity and the precise perceived cutoff require visual inspection. Do not label the scaling formula itself wrong without checking pinned Phaser source and rendering at known camera offsets.

The proper fix is background composition, not more fog over repeated whole-scene images. Separate continuous structural trunks from finite canopy/crown decorations. Keep an opaque atmospheric base covering the viewport at all times. Build bounded, camera-relative pools of deterministic world-space sections, with trunks continuing across section joins and foliage clustered irregularly. Use original full images only where their finite silhouette/composition makes sense. Horizontally seamless artwork must not be assumed vertically seamless.

Reuse stepForestEffects and frame.forestCorruption; do not rename that shared field just to generalize its consumers. Its current tau is 2200 ms and neutral is 0.2. Wind/snow appearance consumes that smoothed value. Independent weather enable/intensity controls are visual parameters, not new sensor algorithms or gameplay wind forces.

## Recommended interfaces

Proposed types, not existing repository APIs:

- VisualEnvironment: seed, theme (forest/wind/snow/combined), wind {enabled, intensity01, directionX}, snow {enabled, intensity01}, optional fog01. Clamp finite values at the public entry point. Default forest with weather off. Keep this configuration renderer-local initially; do not extend shared SectionData until the level owner agrees.
- createAtmosphere(scene, initial): setEnvironment(config), setPreview(partial | null), update({corruption01, deltaMs, reducedMotion, paused, camera}), destroy(). Use a typed interface in config if both UI/game need it, preserving lane import rules. Full event payloads must validate fields, reject NaN/Infinity, and restore base environment settings when overrides clear.
- createVerticalForest(scene, seed): update(camera, corruption01, altitude01), destroy(). Pure seeded section-layout helpers should be independently testable. Weather and background are separate modules; forest-world continues to own platform skins and syncPlatforms.
- One narrow ClimbScene connection after existing effects calculation, with read-only camera/player context. Do not change camera bounds/follow, world time, platform simulation, wax, recovery, saves or procedural generator. Future level owner calls setEnvironment; preview overrides layer on top and never mutate authored configuration.

Weather appearance: preallocate a hard-capped pool (initial budget, e.g. 48 snow flakes + 20 leaves, tune by measurement). Far/near snow uses different speed/opacity, with seeded trajectories and wrapped screen coverage. Visual wind shifts snow drift and leaves; it never writes windAt or stepPlayer inputs. Corruption continuously blends white/blue toward muted crimson/purple, with restrained fog/color changes. Keep flakes/leaves below protected readability layers and sparse near the player. Fade enabling/disabling/intensity through the existing dt-based smoothing primitive or a small visual-parameter helper; do not smooth corruption a second time. Pause freezes particle clocks; reduced motion suppresses drift and looping sprite animation, while maintaining static atmosphere and smooth color changes. Smoothing state must not retain old preview settings after Restore.

## Vertical background design

Use a layered sky/atmospheric foundation plus structural trunks and finite foliage. Establish actual native-pixel anchors before implementation. Derive each parallax layer's visible world interval from camera bounds and its factor; support negative coordinates using floor division. Determine visible chunk IDs with an overscan margin and populate a bounded reusable pool. Chunk layout derives solely from seed, layer ID and integer chunk coordinate. Returning downward to a chunk reconstructs the same arrangement, independent of elapsed time or visit order.

Trunks crossing joins need shared boundary anchors: derive each boundary's anchor set from its boundary ID, then connect matching trunks through adjacent chunks. Use sufficiently tall verified crops, authored modular trunk joins or compatible seam-free trunk pieces, rather than stretching full tree scenes or placing a rectangular image edge in view. Select only interior trunk strips where their join can actually be made continuous; inspect every crop. Crowns, branches and foliage are finite sprites with transparent silhouettes, placed as stable clusters that overlap section joins and vary in asset choice, spacing and permitted mirroring. Avoid adjacent identical motifs and excessive scale variance; use integer source-pixel scales and rounded draw positions. Do not flip directional lighting indiscriminately.

For any background plates blended across chunks, use complementary masks whose weights sum to one over the overlap. Transparent overlays alone do not guarantee coverage or eliminate doubled trunks. Keep structural anchor continuity underneath the blend; fog is supplementary atmosphere, not a seam repair. Prefer precomputed local crops/masks over runtime texture generation each frame. Validate actual pixel continuity; if existing packs lack suitable joinable trunks, document that limitation and author/select compatible pieces under the verified license before promising seamless coverage.

Altitude is a presentation input: gradually transition dense undergrowth to taller trunks, canopy clusters and more open sky using overlapping smooth weights. Do not impose stage boundaries or progression logic. Finite authored routes may supply normalized altitude; indefinite routes need a documented stable height-band mapping with no hard repeating biome reset. Existing healthy/dark tint pairs share the exact layout and anchors, so corruption never relocates trees. Apply the same corruption to added scenery without a second detector or independent decay timers.
