## Goal

With `?source=sim`, the pieeg.js simulator drives a real, staged, tested pipeline that publishes `ComposureState`,
switchable algorithms, a recorder, a headless evaluation script and a full debug overlay. Swapping the simulator for
the real board in P3 is a one-line source change. The game, UI and audio do not change at all.

## Facts this plan relies on (read from `public/vendor/pieeg.js`, 1.3.0-octopus)

| Fact | Line | Consequence |
|---|---|---|
| `connectSimulator({ device })` starts a `setInterval`; it never calls `navigator.bluetooth.requestDevice` | 1145–1236 | The simulator can start on page load, without a click. |
| `triggerSimEvent('alpha' \| 'blink' \| 'clench' \| 'noisy_pin', value)` | 1243 | `SimSource` maps our keys (`Digit1`–`Digit4`, from config) to these. |
| Clench adds ±70 µV of per-sample random noise; noisy pin adds 50 Hz mains plus noise to one channel | 1196–1216 | Clench is broadband, so beta rises even with a 40 Hz low-pass. The noisy pin must lower `quality`, not move the features much. |
| `onBandPowers((powers, spectrum))`: `powers` is `{ Delta, Theta, Alpha, Beta, Gamma }` averaged across channels; `spectrum` is `{ psd, freqs, bandPowers, totalPower, dominantFreq }` with typed arrays | 1585–1617 | The adapter converts both to our `BandFrame` (plain arrays, lower-case band names). |
| `getContactQuality()` gives per-channel `status: 'good' \| 'railed' \| 'flat'`; `getStats()` gives `packetLossRate` | 1366, 1462 | `contactGood01` = share of `good` channels; `packetLoss01` = `packetLossRate`. |
| Defaults: bandpass 1–40 Hz order 5, notch off, Hampel on; Gamma band is 30–100 Hz | 63–68, 678 | We pass our filter config explicitly. v1 does not use gamma. |

## Tasks and acceptance tests

### P1.1 Sources (do first; everything else depends on `BandFrame` arriving)

1. `pieeg-types.ts`: declare the subset of `PiEEG` we use; read the global through one function that throws a clear
   error if `index.html` did not load the script. Nothing else in the repo touches `window.PiEEG`.
2. `pieeg-adapter.ts`: create `new PiEEG({ updateHz, filter })` from `SIGNAL_CONFIG`; on `onBandPowers` build a
   `BandFrame` with `contactGood01` and `packetLoss01` from the SDK; on `onError` / `onDisconnect` report up.
3. `sim-source.ts`: `connectSimulator({ device: 'octopus-16' })`; keydown on `simKeys` → `triggerSimEvent`. Alpha is
   a toggle (the SDK's behaviour); clench and blink are one-shots; noisy pin toggles. The keys listen on `window`
   and ignore key repeat.
4. `replay-source.ts` + `recording-format.ts`: read JSONL (`{"t":…,"bands":…,…}` per line, first line a header with
   algorithm, config snapshot and date); play at 1× or faster; a headless mode with no timers for tests and tools.

| Acceptance test | How |
|---|---|
| Simulator frames arrive at about 12 Hz | Browser, `?source=sim`: overlay sample age stays under 200 ms. |
| Holding the alpha key changes the bands | Overlay: alpha share rises within 2 s of pressing `1`, falls after pressing it again. |
| Replay is fast and headless | Unit test: a 10 s fixture replays to completion in under 1 s, frames in order, timestamps preserved. |
| No device code outside the lane | Lane-boundary test still passes; `rg -n "PiEEG" src --glob '!src/signal/**'` finds nothing. |

### P1.2 Features, quality, freshness

1. `features.ts`: from the spectrum, using our own band edges, compute
   - **resting feature** `a = α / (θ + α + β)`;
   - **active-play feature** `m = β / (θ + α + β)` (v1 ignores gamma: the 40 Hz low-pass removes most of it).
   If the spectrum is missing, use the SDK band powers instead. Say in the header comment that `m` is partly muscle.
2. `quality.ts`: `quality = contactGood01 × (1 − packetLoss01)`, each defaulting to 1 when unknown, clamped to 0..1.
3. `preprocess.ts`: reject frames with NaN or negative powers; `fresh = nowMs − frame.t ≤ staleAfterMs`.

| Acceptance test | How |
|---|---|
| An alpha rise raises the resting feature | Fixture with alpha × 3 for 5 s: mean `a` during the burst > 1.5 × mean before. |
| A clench raises the active feature | Fixture with broadband noise added: mean `m` rises. |
| A noisy pin lowers quality, not the features | Fixture with `contactGood01 = 15/16` and one channel's noise: `quality` drops; `a` and `m` move < 10 %. |
| A gap makes the state stale | Fixture with a 600 ms gap: `fresh` is false for frames judged after 500 ms. |

### P1.3 Calibration (pure functions; the screens are P6.1)

1. `calibrateBaseline(samples, kind)` returns `{ low, high }` or `null` with a reason key. Active-play: `low` = median
   of relaxed play, `high` = 90th percentile of the clench window. Resting: `low` = eyes-open median, `high` =
   eyes-closed median.
2. **Repeatability check**: split each window in two halves; fail if the halves' medians differ by more than 25 %.
3. **Separation check**: fail if `high < 1.3 × low` (the brief's eyes-closed rule, applied to both baselines).
4. `SignalControl.calibrate(step)` collects `calibration.<step>Ms` of fresh, valid frames and emits
   `calibration_result` on the bus.

| Acceptance test | How |
|---|---|
| A good calibration passes | Fixture with clear separation → `ok: true`, sensible `low < high`. |
| A bad calibration is detected | Fixture where eyes-closed alpha is not above eyes-open → `ok: false`, reason `calibration.noSeparation`. |
| Unrepeatable data is detected | Fixture where the two halves disagree → `ok: false`, reason `calibration.unstable`. |
| Stale frames do not count | Calibration over a fixture with a gap uses only fresh frames. |

### P1.4 Scorer, smoother, gates, registry, pipeline

1. `scorer.ts`: normalise each feature against its baseline to 0..1; before calibration use a neutral default
   (intensity = `neutralIntensity`, resting = 0) and set `calibrated = false`.
2. `smoother.ts`: time-based exponential smoothing `prev + (target − prev) × (1 − e^(−dt/τ))`, the same formula as
   the effects engine, with `intensityTauMs` and `restingTauMs`.
3. `gates.ts`:
   - **Validity:** `valid = fresh && quality ≥ qualityFloor && calibrated`.
   - **Invalid → ease to neutral:** intensity eases toward `neutralIntensity`; `restingActive` is forced false.
   - **Hysteresis:** `restingActive` turns on at `≥ on`, off at `≤ off`.
   - **Fixed mode:** `mode: 'fixed'` holds intensity at `neutralIntensity`; resting still works (feature BCI-6).
   - **`held`** stays false in P1 (the camera gate that would set it is deferred).
4. `registry.ts`: `{ 'intensity-v1': …, 'passthrough-v0': … }`; unknown id falls back to the default with a console
   warning.
5. `url-params.ts`: `?source=sim|replay|live`, `?algo=<id>`, `?mode=fixed`, `?replay=<file under /recordings/>`.
6. `pipeline.ts` wires the stages; `index.ts` builds the `SignalHandle` from it. `connect('LIVE_EEG')` throws
   "not available until P3" for now.

| Acceptance test | How |
|---|---|
| A new algorithm is one file plus one line | `passthrough-v0.ts` + a registry line; `?algo=passthrough-v0` shows on the overlay; no other file changed. |
| Hysteresis | Unit test: a resting value oscillating between 0.5 and 0.55 never flips `restingActive` after it is on. |
| Invalid data eases, never jumps | Unit test: when frames stop, intensity moves toward neutral and never changes by more than the smoother allows per step. |
| Fixed mode | `?mode=fixed`: intensity stays at neutral while resting still responds to the alpha key. |
| The game is unchanged | `git diff --stat main -- src/game src/audio src/content` is empty. |

### P1.5 Recorder and evaluation

1. `recorder.ts`: records every `BandFrame`, the published `ComposureState` and every bus event, with timestamps, to
   JSONL in memory; a debug-overlay button (and `Shift+R` while the overlay is open) downloads it. **Band powers,
   quality and events only. Never raw samples. No names in the file.**
2. `tools/eval/run-eval.ts <algo> <recording.jsonl> [--speed N]` replays a recording headlessly through the chosen
   algorithm and prints a table: seconds valid, intensity mean / min / max, resting-active seconds, on/off flips per
   minute, calibration outcome if the recording contains one.
3. Generate `recordings/sim-fixture.jsonl` (30 s, scripted alpha and clench events) with the fixture generator, so
   evaluation works before any real recording exists.

| Acceptance test | How |
|---|---|
| Evaluation runs headless | `npm run eval -- intensity-v1 recordings/sim-fixture.jsonl` prints the table and exits 0. |
| Two algorithms can be compared | Running it with `passthrough-v0` prints different numbers from the same file. |
| A browser recording replays | Record 20 s in the browser, download, `?source=replay&replay=<file>` reproduces the overlay values. |

### P1.6 Diagnostics

1. Debug overlay shows: source, algorithm, mode, both raw features, both normalised scores, quality (with contact and
   packet-loss parts), sample age, valid, calibrated, `restingActive` with its on/off thresholds, lantern radius, ember
   progress; plus the recorder's download button and the simulator key legend when the source is SIM.
2. Two developer buttons, **Calibrate active** and **Calibrate resting**, call `SignalControl.calibrate()` and show the
   result. Without them nothing could calibrate until the P6.1 screens exist, and an uncalibrated state is never
   valid, so the lantern would sit at neutral. They are also how the midnight checkpoint (P3.3) is run.
3. The source badge already covers DIA-1. Check it reads `RECORDED REPLAY` for `?source=replay`.

| Acceptance test | How |
|---|---|
| Every DIA-2 field is visible | Screenshot of the overlay with the simulator running. |
| Badge stays visible with the overlay hidden | Toggle the overlay; the badge remains. |
| Calibrate, then the lantern responds | SIM: run both calibrations (pressing `2` during active, `1` during resting); afterwards `valid` is true and pressing `2` visibly shrinks the light. |
