## Contract changes and integration requests

None in this PR. Reuse UiDeps, UiComponent, Settings, GameSnapshot and existing bus events.

- Stores.snapshot is game-owned: menus must not write game phases themselves. Pause/resume can emit existing events, but actual physics/timer suspension needs the game owner to implement/verify consumption. Main-menu start has no start event in the frozen contract; ask Srishan for the intended start route before P2.2. Do not invent an event or ship an inert button.
- Settings values update live through the existing store. Actual game key remapping, audio volumes and effects are consumed by their respective owners; a working panel is insufficient evidence that those integrations work.
- P2.4 cannot import src/content directly under the lane rule. Narrator events currently contain only lineId. Ask Srishan for a shared read-only caption lookup/dependency providing reviewed text and duration. Keep fixture lookup local to UI tests until that seam exists; no duplicate production line bank or cross-lane import.

## Tasks and acceptance tests

### P2.1 Shell — first implementation task

1. Audit and extend existing theme tokens and named slots. Keep local system fonts, pointer-through canvas areas and clear keyboard focus. Preserve the source badge and debug overlay behavior.
2. Extend settings validation beyond matching JavaScript types: enforce documented 0..1 volume/effect ranges, finite positive caption scale and usable nonempty key codes. Invalid saved fields fall back safely without mutating shared defaults; preserve valid siblings. Specify any extra caption scale bounds in the P2.1 implementation notes before use.
3. Retain live store notifications and persistence. Handle malformed JSON, denied storage reads and failed writes without interrupting the session.
4. Verify registry visibility, disabled components and cleanup against current contracts; extend only what is missing. Preserve diagnostic string keys and existing exports.

| Acceptance test | Verification after approval |
|---|---|
| One token restyles UI | Temporarily change the accent token in browser devtools and inspect all currently mounted consumers; restore it. No hardcoded duplicate component palette. |
| Corrupt storage falls back | Unit cases: malformed JSON, wrong types, nonfinite/out-of-range numbers, missing/unknown fields, throwing storage. Valid siblings survive and defaults remain unchanged. |
| Live settings persist | Subscribe, change settings, verify notified value and serialized storage, then reload store. Failed storage writes still notify session subscribers. |
| Slot and phase lifecycle works | Mount fixture components; assert slot placement, initial and changed phase visibility, disabled omission, and subscription/DOM cleanup on unmount. Use available test tooling; no dependency changes without Srishan. |
| Diagnostics remain usable | Chrome smoke check: source badge remains visible, backtick toggles overlay, slot backgrounds do not block canvas controls. |
| Required gate | npm run check passes; record actual counts and unverified items in report. |
