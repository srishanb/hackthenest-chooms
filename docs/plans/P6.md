## Goal

After a fall, R starts a recovery: gameplay freezes, the view steadies and brightens, and the ember fills only while
the signal is valid, fresh and `restingActive`. Lapses pause it and never reset it. When full, the player returns to
the last safe ledge before the fall. Cancel keeps the ember; a labelled ordinary-input rescue spends it. FAL-2 was
removed (f4415d9), so a fall is never reset to a checkpoint: the ember is the only way back up.

## Tasks and acceptance tests

### P6.2 Ember machine and return anchor (pure; can start before P4 lands)

1. States: `idle → eligible → activating ⇄ recalibrating`, leaving by `returned` or `cancelled` (both back to
   `idle` or `eligible`). PLAN's `requesting` is the transition that emits `ember_requested`, not a resting state.
2. `stepEmber(state, input, dtMs, config) → { state, events, promptKey }`. Input: `counts`, `grounded`, `charging`,
   key presses, `emberAvailable`, `anchorUseful`, `calibrationDone`.
3. Anchor (EMB-3): remember the last ledge stood on whose platform type is `anchorSafe` and at least as wide as the
   player. At takeoff (jump or walk-off) copy it. On landing at least `minFallPxToOffer` lower, it becomes the anchor.
4. Eligible only if: ember owned, anchor still higher by `minFallPxToOffer` (in any section: a fall from section 2
   into section 1 qualifies), player grounded, not charging. Climbing back to the anchor's height clears it; a
   later fall replaces it with that fall's takeoff ledge. The anchor is memory only: a reload resumes at the refuge.

| Acceptance test | How |
|---|---|
| Every transition | Unit: one test per arrow in task 1, each checking the emitted events. |
| Anchor is the ledge before the fall | Unit: take off from A, land on lower C → anchor is A, not C. |
| Unsafe ledges never chosen | Unit: fake type `{ anchorSafe: false }` and a too-narrow ledge are skipped. |
| Not offered without a use | Unit: no ember, a small drop, or climbed back to the anchor → stays `idle`. |
| Cross-section fall | Unit: take off in section 2, land in section 1 → eligible; anchor is the section 2 ledge. |

### P6.3 EEG-gated activation (EMB-4, EMB-5, EMB-6)

1. `ember-signal.ts`: `counts = valid && restingActive && (nowMs − state.t) ≤ maxStateAgeMs`; reason `'signal'`
   when invalid or stale, `'resting'` when only `restingActive` is false. Clock: `performance.now()`, injected.
2. Activating: `progressMs += min(dtMs, maxStateAgeMs)` only while `counts`; otherwise unchanged. Never decreases.
   Done at `targetValidMs`. `progress01` goes to the snapshot; `promptKey` is `waitingSignal` on reason `'signal'`.
3. Freeze (EMB-4): phase `'ember'` skips `stepPlayer`; camera `stopFollow` (verified in `phaser.d.ts`); effects get
   the calm end (`atIntensity0`), the path P5.1 adds for `inRefuge`; until then `intensity: 0, valid: true`.

| Acceptance test | How |
|---|---|
| Lapses pause, never reset | Unit, fixture states: 2 s counting, 1 s not, 2 s counting → done at 5 s of wall time. |
| Frozen stream never completes | Unit: `valid: true`, `restingActive: true` but `t` never advances → never done. |
| Invalid never advances | Unit: `valid: false` for 60 s → progress 0. |
| Works end to end | Browser, `?source=sim`: calibrate both, fall, press R, toggle alpha (`1`) → ember fills. |
| Signal access is fenced | `npm run check` runs `signal-access.test.ts` and the lane-boundary test; both pass. |

### P6.4 Cancel, recalibrate, ordinary-input rescue (EMB-9)

1. R while activating or recalibrating → `ember_cancelled`; ember kept, phase `'playing'`; a new try starts at 0.
2. `keys.assist` while activating → return with `via: 'assist'`, spending the same ember. `canAssist` is true for the
   whole activation, so the rescue never depends on the signal. The UI labels it and the badge shows it (DIA-1).
3. `keys.recalibrate` or the event → `recalibrating`: phase stays `'ember'`, counting stops, progress kept. The
   next `calibration_result` returns to `activating`; `ok: false` shows `recalibrateFailed`.

| Acceptance test | How |
|---|---|
| Cancel keeps the ember | Unit: request, cancel → `available` still true, `ember_cancelled` once. |
| Rescue spends it | Unit: request, assist → `ember_returned { via: 'assist' }`, `available` false. |
| Recalibrate keeps progress | Unit, fake bus: 2 s progress, recalibrate, `calibration_result` → back with 2 s. |
| Keyboard only | Browser: R, H and C each work; C is answered by the overlay's **Calibrate resting** button. |

### P6.5 Safe return (EMB-8)

1. On done or assist: put the player on the anchor (x clamped inside the ledge), zero velocity, clear the charge,
   set the jump latch (P4.1). Consume the ember, clear the anchor, save at once (CHK-3), emit `ember_returned`.
   Phase back to `'playing'`; camera `startFollow` again.

| Acceptance test | How |
|---|---|
| No launch on arrival | Unit: jump held throughout activation and return → no launch until release and a new press. |
| Lands safely | Unit: position is on the anchor ledge with feet on top, velocity 0. |
| Spent ember persists | Unit with fake storage: after return, a reload has `emberAvailable: false`. |
